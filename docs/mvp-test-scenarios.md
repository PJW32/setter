# MVP 테스트 시나리오

목적
1. 심사위원이 직접 접속해 써 봤을 때 깨지지 않는지 확인
2. 발표 시연(약 5분) 대본
3. 소개서 "AI 결과의 오류·불확실성 대응" 근거 자료 (발화 테스트 세트 결과)

## 1. 시연 대본 (페르소나: 지방 출신, 판교 IT 회사 합격, 입사 2주 전)

| # | 사용자 입력 | 기대 화면 | 확인할 것 |
|---|---|---|---|
| 1 | "판교역으로 출근해요. 보증금 1000에 월세 60 넘으면 안 되고 통근은 50분 이내였으면 해요. 싼 게 제일 중요하고 조용했으면 좋겠어요. 이웃이 친절했으면 좋겠어요." | 해석 카드: 필수(보증금 ≤1000, 월세 ≤60, 통근 ≤50) / 선호(월 총비용 매우 중요, 조용함 중요, 근거 원문) / **확인 불가: 이웃이 친절했으면** | 필수·선호 구분, 확인 불가 분리 |
| 2 | (자동) 작업 로그 | 조건 추출 → 목적지 판교역 → 후보 시군구 → (수집) → 통근 → 점수 → 설명 | 에이전트가 무엇을 했는지 보임 |
| 3 | (자동) 결과 | 지도 TOP 3, 순위표(요인별 기여도 막대), 산점도(가로 월 총비용, 세로 통근, 파레토 강조), "예산 안 거래 n/m건" | 숫자 근거, 출처 |
| 4 | "아까보다 역 가까운 게 더 중요해요. 통근보다는 역이 더 중요해요." | 단계 변경 표시(역 접근성 ↑), 순위 변동 패널 "○○동 5→3위: 역 접근성 +x점" | 상대적 조정, 비교 순서, **순위 변동 이유** |
| 5 | "통근 30분 이내로 줄이면 어떻게 돼?" | "가정해 보면…" 결과, 실제 조건은 그대로 | 가정 질문(what-if) |
| 6 | "편의점도 많고 조용한 데면 좋겠어" | 상충 안내: "편의시설이 많은 동일수록 주점도 많습니다" + 숫자, 되묻기 | 트레이드오프 설명 |
| 7 | "을지로로 회사가 바뀌면?" 또는 "을지로로 출근해요" | 목적지 을지로입구역, (처음이면) 수집 로그, 새 순위 | 다른 지역에서도 동작 |

시연 전 준비: 판교역·을지로 주변 미리 수집 (`settings.PREWARM_DESTINATIONS`), 키 4개 확인 (`/api/health`).

## 2. 발화 테스트 세트 (조건 추출)

각 발화를 **현재 상태 = 판교역, 모든 요인 보통, 필수 조건 없음**에서 넣고, 변경분이 기대와 맞는지 본다.
"맞음" 기준: 기대 항목이 모두 있고, 금지 항목이 없음 (단계는 방향만 맞으면 통과: ↑ = 보통보다 위).

| # | 발화 | 기대 | 금지 |
|---|---|---|---|
| 1 | 월세가 제일 중요해 | monthly_cost = 매우 중요 | 필수 조건 |
| 2 | 통근은 1시간까지 괜찮아 | max_commute_min = 60 | commute ↑ |
| 3 | 보증금 500에 월세 50 이하로만 | max_deposit = 500, max_monthly_rent = 50 | |
| 4 | 싸면 좋겠어 | monthly_cost ↑ | 필수 조건 |
| 5 | 역세권이었으면 좋겠어 | station_access ↑ | |
| 6 | 조용한 동네가 좋아 | quiet ↑ | |
| 7 | 편의점 많고 조용한 데 | convenience ↑, quiet ↑, follow_up(상충) | |
| 8 | 이웃이 친절했으면 | unsupported 에 포함 | 요인 변경 |
| 9 | 밤길이 안전했으면 좋겠어 | unsupported 에 포함 | quiet 변경 |
| 10 | 통근보다 월세가 더 중요해 | comparisons(monthly_cost > commute), 결과 단계 순서 지킴 | |
| 11 | 편의시설은 상관없어 | convenience = 상관없음 | |
| 12 | 오피스텔만 볼래 | house_types = [오피스텔] | |
| 13 | 강남역으로 출근해요 | destination = 강남역 | |
| 14 | 회사가 카카오 판교아지트야 | destination = 카카오 판교아지트 | |
| 15 | 월세 한도는 없어도 돼 | clear_constraints 에 max_monthly_rent | |
| 16 | 한 달에 총 80만원 넘으면 안 돼 | max_monthly_cost = 80 | |
| 17 | 보증금 1억까지 가능해 | max_deposit = 10000 | |
| 18 | 통근 30분 이내면 어떻게 돼? | intent = what_if, max_commute_min = 30 | |
| 19 | 관리비 싼 곳 | unsupported(관리비) 또는 monthly_cost ↑ + 관리비 확인 불가 안내 | 관리비를 데이터로 계산했다는 표현 |
| 20 | (상태: 월 총비용 매우 중요) 아까보다 월세는 덜 중요해 | monthly_cost = 중요 | |

실행: `python scripts/eval_utterances.py` (실제 Gemini 호출, 결과를 표로 출력하고 `data/raw/eval_utterances.json` 에 저장). 결과(통과율, 실패 사례와 원인)를 소개서에 싣는다.

| 실행 | 모델 | 통과 | 비고 |
|---|---|---|---|
| 2026-11-21 1회차 | gemini-3.8-flash (Vertex) | **20/20** | 코드 교정(비교 순서) 0건. 1회 결과라 제출 전 3회 이상 반복해 흔들림 확인 필요 |

### 실제 API 점검 기록 (`scripts/smoke_agent.py`)

2026-11-21, 저장소가 빈 상태에서 판교 시나리오 3턴:

| 턴 | 발화 | 결과 | 시간 |
|---|---|---|---|
| 1 | 판교역 출근, 보증금 1000·월세 60 이하, 통근 50분 이내, 싼 게 제일, 조용, 이웃 친절 | 후보 시군구 13곳 새로 수집(동 302곳, 실거래 132,076건) → 반경 10km 후보 동 71곳 → 통과 59곳. 1위 이매동·2위 산성동·3위 서현동. "이웃이 친절했으면"은 확인 불가로 안내. 설명 숫자 검사 통과 | 235초 (수집 포함) |
| 2 | 아까보다 역 가까운 게 더 중요, 통근보다 역이 더 중요 | 역 접근성 보통→중요. 삼동 5→4, 풍덕천동 9→6 등 순위 변동 설명 | 13초 |
| 3 | 통근 30분 이내로 줄이면? | what_if 로 인식, 통과 39곳, 실제 조건은 그대로 | 11초 |

- 시군구 1곳 수집: 도시 지역 5~11초, 넓은 농촌형(용인 처인구·광주시, 법정동 82곳) 55~67초
- 대화 한 턴 대부분은 Gemini 설명(8~10초). 점수 계산은 30ms 안팎

## 3. 예외 상황

| 상황 | 기대 동작 | 자동 테스트 |
|---|---|---|
| 목적지 없이 조건만 말함 | 조건은 저장하고 목적지를 되묻는다 | `test_asks_destination_first` |
| 지도에서 못 찾는 목적지 | "찾지 못했어요" + 다시 묻기 | `test_unknown_destination_asks_again` |
| 조건이 너무 빡빡해 통과 0~2곳 | 아깝게 탈락한 동 3곳 + 얼마나 풀면 되는지 | `test_near_misses_when_nothing_passes` |
| 실거래가 적은 동 | "월 총비용 데이터 부족", 중앙값으로 채움, 예산으로 제외 안 함 | `test_missing_cost_*`, `test_unverified_budget_*` |
| 역이 없는 동 | 역 접근성 60분(멀다)으로 처리 | `test_no_station_is_far_not_missing` |
| LLM 설명에 없는 숫자 | 재작성 → 템플릿 설명 | `test_full_turns_with_diff_and_number_check` |
| LLM JSON 실패 | 1회 재시도 → "다시 말해 주세요" | (수동) |
| 가정 질문 | 결과만 보여주고 상태 유지 | `test_what_if_does_not_commit` |
| 대중교통 API 한도 초과 | 해당 동 "통근 데이터 없음", 나머지는 계속 | (수동) |
| 시군구 수집 실패 | 그 시군구만 빼고 계속, 로그에 오류 | (수동) |

## 4. 통과 기준 (제출 전 체크리스트)

- [ ] `python -m unittest discover -s tests` 전부 통과
- [ ] `python scripts/smoke_agent.py` 판교 3턴이 오류 없이 끝남, 설명이 숫자 검사 통과
- [ ] 발화 테스트 세트 통과율 기록 (목표 18/20 이상), 실패 사례 원인 정리
- [ ] 시연 대본 1~7 을 배포 주소에서 끝까지 실행
- [ ] 처음 보는 목적지 1곳(예: 을지로)으로 실시간 수집이 끝까지 됨, 소요 시간 기록
- [ ] `/api/health` 에서 키 4개 OK, 지출 한도 설정 (Gemini, 카카오 유료 쿼터)
- [ ] 화면에 출처·기준 시점·"시세 참고용"·"확인 불가" 표시
