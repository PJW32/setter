# 에이전트 응답 형식

대화 에이전트가 사용자에게 **무엇을, 어떤 모양으로, 무엇과 함께** 답하는지 한 곳에 정리한 문서.
답변 문구·길이·자료를 고칠 때, 소개서의 "AI 결과의 오류·불확실성 대응"을 쓸 때 기준으로 쓴다.

- 기준 시점: 2026-11-22 (PR #11 병합 후)
- 관련 코드: `backend/agent.py`(분기), `backend/prompts.py`(형식 규칙), `backend/presenter.py`(facts·자료·템플릿), `backend/guides.py`(확인 방법), `backend/llm.py`(숫자 검사)
- 관련 문서: [backend.md](backend.md) 6절(처리 흐름), [api-spec.md](api-spec.md) 7절(이벤트 필드)

---

## 1. 한눈에 보기

| 응답 종류 | 언제 | 누가 쓰나 | 길이 | 함께 가는 자료 | 오른쪽 화면 |
|---|---|---|---|---|---|
| **짧은 대답** | 인사·감사·확인 ("고마워요", "좋아") | 코드 (고정 문구) | 1문장 | 없음 | 그대로 |
| **질문 답변** | 조건은 그대로, 지금 결과에 대한 질문 | Gemini (`ANSWER_SYSTEM`) | 1~4문장 | 질문한 동네 표, 비교 표·막대 차트, 확인 방법 | 질문에 맞춰 이동 |
| **결과 설명** | 조건이 바뀜 (가정 질문 포함) | Gemini (`EXPLAIN_SYSTEM`) | 6줄 이하 | 상위 3곳 표(또는 말한 동네), 확인 방법 | 새 결과로 갱신 (+ 말한 동네로 이동) |
| **되묻기** | 목적지가 없음, 목적지를 못 찾음 | 코드 (고정 문구) | 1문장 | 없음 | 그대로 |
| **대체 답변** | Gemini 답이 숫자 검사를 두 번 통과하지 못함 | 코드 (템플릿) | 몇 줄 | 위와 같음 | 위와 같음 |

화면의 말풍선에서 `source` 가 `template` 이면 "자동 요약" 표시가 붙는다 (짧은 대답·되묻기·대체 답변).

## 2. 어떤 응답이 나가는지 (분기)

```
사용자 발화
 → [Gemini] 의도·변경분·가리킨 동네·데이터 밖 주제 추출
 → 조건 변경이 있나? (목적지·필수 조건·선호 단계·주택 유형)
     ├ 없음 + 의도가 인사·확인              → 짧은 대답
     ├ 없음 + 지금 결과 있음                 → 질문 답변 (순위 재계산 없음)
     ├ 없음 + 결과 없음                      → 되묻기 (목적지)
     └ 있음                                  → 결과 설명 (가정 질문이면 상태는 그대로)
```

`intent` 값: `update`(조건 변경) · `what_if`(가정) · `question`(질문) · `confirm`(확인) · `smalltalk`(인사·감사) · `other`

## 3. 응답 종류별 형식과 예시

### 3.1 짧은 대답 (`presenter.short_reply`)

LLM·엔진을 부르지 않는다 (조건 해석 1회만). 2~4초.

| 발화 | 결과가 있을 때 | 결과가 없을 때 |
|---|---|---|
| 감사 ("고마워요") | 도움이 됐다니 다행이에요. 다른 동네나 조건이 궁금하면 편하게 물어보세요. | (같음) |
| 인사 ("안녕하세요") | 안녕하세요! 지금 결과에서 궁금한 동네를 묻거나 조건을 바꿔 보세요. | 안녕하세요! 어디로 출근하는지와 예산을 알려 주시면 살기 좋은 동네를 찾아 드릴게요. |
| 확인 ("좋아") | 좋아요, 지금 조건으로 볼게요. 바꾸고 싶은 점이 생기면 말씀해 주세요. | 좋아요. 출근할 곳과 예산을 알려 주세요. |
| 그 밖 | 지금 결과에 대해 묻거나(예: '정자동은 어때?'), 조건을 바꿔 보세요(예: '월세 70까지 괜찮아'). | 출근할 곳, 예산, 중요하게 생각하는 점을 알려 주시면 동네를 비교해 드릴게요. |

### 3.2 질문 답변 (`prompts.ANSWER_SYSTEM`)

| 규칙 | 내용 |
|---|---|
| 길이 | **결론부터, 1~4문장** |
| 나열 | 여러 동네·항목은 줄을 나눠 `· 이매동: 월 총비용 61만 원, 통근 15분` (최대 4줄) |
| 중심 | 질문한 동네(`대상_동네`)를 중심으로. 묻지 않은 상위 3곳 설명은 반복하지 않음 |
| 제외된 동 | 제외 이유와 "얼마나 풀면 들어오는지"를 말함 |
| 후보 밖 동 | "지금 목적지 주변 후보에 없다, 목적지를 바꾸면 볼 수 있다" |
| 모르는 정보 | 솔직히 없다고 말하고 확인 방법 한 줄. 가까운 정보가 있으면 덧붙임 (맛집 → 편의시설 수) |
| 다시 가리키기 | "그 동네·거기·두 곳" → 직전 답변의 동네 (`최근_대화`도 참고) |

예시 (판교역, 보증금 1000·월세 60 이하, 싼 게 제일. 2026-11-22 실제 응답을 일부 줄임. 숫자는 그대로)

> **정자동은 왜 순위에 없어?**
> 정자동은 조건에서 제외된 것이 아니라, 조건을 만족한 동네 중 24위(69.9점)에 있어요.
> 통근은 12분으로 가깝지만, 가장 중요하게 보신 월 총비용이 68.3만 원이라 점수가 낮게 반영됐어요.
> 📋 표: 24위 정자동 · 🗺️ 지도에서 정자동 선택

> **1위랑 2위 비교해줘**
> 1위 이매동은 통근과 교통비에서 앞서 점수가 3.8점 높고, 2위 풍덕천동은 월 총비용과 역 접근성에서 앞서요.
> · 이매동: 월 총비용 61만 원, 통근 15분, 역까지 도보 8분
> · 풍덕천동: 월 총비용 60.5만 원, 통근 17분, 역까지 도보 2분
> 📋 비교 표 + 요인별 점수 막대 · 🗂️ '후보 비교' 탭에 두 동네

> **이매동에 맛집 많아?**
> 맛집 정보는 서비스 데이터에 없어 바로 확인하기 어려워요. 지도 앱에서 '이매동 맛집'으로 검색해 보세요.
> 참고로 이매동 생활 중심 반경 안에는 편의점 14곳, 약국 12곳, 대형마트 7곳, 주점 9곳이 있어요.
> 🔗 카카오맵에서 '이매동 맛집' 검색

### 3.3 결과 설명 (`prompts.EXPLAIN_SYSTEM`)

**6줄 이하, 마크다운 기호 없이 줄바꿈으로.** 아래 예시는 2026-11-22 실제 응답 (치안을 함께 말한 경우).

| 줄 | 내용 |
|---|---|
| 1 | 핵심 한 문장. 순위가 바뀌었으면 무엇 때문에 누가 올라갔는지 (요인별 변화 중 큰 것 하나). 가정 질문이면 "가정해 보면 … 실제 조건은 그대로예요" |
| 2~4 | 상위 동네를 한 줄씩 `1위 이매동: 월 총비용 61만 원, 통근 15분` (가장 큰 강점 1~2개를 실제 값으로. '기여점수' 같은 내부 용어 금지). 말한 동네가 있으면 그 줄 먼저 |
| 5 | 주의할 점 하나만 (데이터 부족, 예산 안 거래가 적음, 상충, 조금 풀면 들어오는 동). 첫 결과면 "실거래가는 시세 참고용이에요" |
| 6 | 확인 불가 조건이 있으면 "직접 확인이 필요해요" + 방법. 되물을 것이 있으면 마지막 줄에 질문 |

예시

> 판교역 통근과 월 총비용을 중심으로 추천 동네를 정리했어요.
> 1위 이매동: 월 총비용 61만 원, 통근 15분
> 2위 풍덕천동: 월 총비용 60.5만 원, 역까지 도보 2분
> 3위 서현동: 월 총비용 61.4만 원, 통근 20분
> 이매동은 예산 안 거래가 26건으로 적은 편이며, 실거래가는 시세 참고용이에요.
> 치안은 직접 확인이 필요해요. 생활안전지도나 밤 시간 현장 방문을 추천해요.

### 3.4 되묻기

| 상황 | 문구 |
|---|---|
| 목적지가 없음 | 어디로 출근(통학)하시나요? 역 이름이나 회사 이름을 알려주세요. |
| 목적지를 지도에서 못 찾음 | '{입력}'을(를) 지도에서 찾지 못했어요. 역 이름이나 회사 이름으로 다시 알려주시겠어요? |
| 해석 실패 (JSON 두 번 실패) | 말씀을 잘 이해하지 못했어요. 출근지, 예산, 중요하게 생각하는 점을 한 번 더 말씀해 주세요. |

Gemini 가 낸 되묻기(`follow_up_question`, 예: 편의시설 많고 조용한 곳 → 상충 확인)는 결과 설명의 마지막 줄로 나간다.

## 4. 모든 답변에 공통인 규칙

| 규칙 | 이유 | 지키는 곳 |
|---|---|---|
| **엔진이 계산한 숫자만 쓴다.** 차이는 코드가 계산해 넘긴 값(`비교.차이_크기`, `더_나은_쪽`)만 | 숫자를 지어내지 않게 | 프롬프트 + 숫자 검사 (5절) |
| 존댓말, 마크다운 기호(`*`, `#`, `**`) 금지 | 말풍선이 줄바꿈만 보여줌 | 프롬프트 |
| 매물(집)은 추천하지 않고 동네만 | 서비스 범위 | 프롬프트 |
| 실거래가는 "시세 참고용" (첫 결과에 한 번) | 과거 계약이지 현재 가격이 아님 | 프롬프트 + 화면 하단 고정 문구 |
| 데이터로 확인할 수 없는 조건은 지어내지 않고 "확인 불가"로 | 신뢰 | 조건 해석 프롬프트 + 확인 방법 (7절) |

### 4.1 숫자 표기

| 단위 | 표기 | 예 |
|---|---|---|
| 분, 곳, 개, 건, 회, 원, 위 | **정수** | 통근 15분, 주점 9곳, 표본 69건, 1위 |
| 만원, 점 | **소수 첫째 자리**, `.0` 은 뗌 | 월 총비용 61만 원 / 60.5만 원, 85점 / 80.1점 |

- 코드: `presenter.by_unit()` 이 facts·화면 자료·비교 차이를 이 규칙으로 맞춤 (`INT_UNITS`)
- 프롬프트에도 같은 규칙. 숫자 검사는 `61.0` 과 `61` 을 같은 수로 본다

## 5. 숫자 검사와 대체 답변 (`llm.unknown_numbers`)

1. Gemini 답변에서 숫자를 모두 뽑는다 (쉼표 제거, `61.0` = `61`)
2. 넘겨준 facts 에 없는 숫자가 있으면 **한 번 다시 쓰게 한다** ("facts 에 없는 숫자 [..]가 있었다")
3. 그래도 있으면 **코드 템플릿 답변**으로 바꾼다 (`template_explanation`, `template_answer`) → `source = template`
4. 1~10 은 순위 표현으로 허용

작업 로그에는 `설명 완료 (숫자 검사 통과)` 또는 `… 템플릿으로 대체` 가 남는다.

## 6. 함께 보내는 자료와 화면 연동

`message` 이벤트 = `text` + `source` + `attachments` + `focus` ([api-spec.md](api-spec.md) 7절)

### 6.1 대화창 자료 (`attachments`)

| 종류 | 언제 | 내용 |
|---|---|---|
| 동네 표 `dongs` | 결과 설명(상위 3곳 또는 말한 동네), 질문 답변(질문한 동네) | 순위 또는 "조건 밖", 월 총비용, 통근, 역까지, 제외 이유. 동네마다 "지도에서 보기" |
| 비교 표 `dongs.compare` | 동네가 정확히 두 곳 | 점수·월 총비용·월세·보증금·교통비·통근·역 도보·주점의 값과 **유리한 쪽** |
| 요인별 점수 막대 `compare.factors` | 비교 표와 함께 | 두 동네의 요인별 점수 (합 = 총점) |
| 확인 방법 `guides` | 데이터 밖 정보를 물었을 때 | 주제, 확인 방법, 링크 |

### 6.2 오른쪽 화면 연동 (`focus`, `presenter.focus_for`)

| 질문 | 화면 |
|---|---|
| 동네 두 곳 이상, 또는 "비교·차이·어디가 더" | **후보 비교** 탭에 그 동네들을 나란히 |
| 통근·비용 질문 ("통근, 출근, 비용, 월세, 보증금, 교통비, 싸, 비싸") | **비용·통근** 산점도에서 그 동네를 주황 테두리로 강조 (조건을 통과한 동만) |
| 동네 한 곳 | **지도**에서 그 동네 선택 |
| 질문한 동네가 없음 | 화면 그대로 |

조건이 바뀌어 새 결과가 나오면 강조는 지운다. 휴대폰 화면에서는 대화 중 결과 화면으로 자동 전환하지 않는다.

## 7. 모르는 정보를 물었을 때

| 경우 | 답변 방식 |
|---|---|
| 정해 둔 주제 (아래 12개) | "데이터에 없다" + 고정된 확인 방법과 공식 링크 |
| 그 밖의 주제 (맛집, 카페 …) | "데이터에 없다" + **카카오맵에서 '{동네} {주제}' 검색** 링크 |
| 지금 후보에 없는 동네 | "지금 목적지 주변 후보에 없다, 목적지를 바꾸면 볼 수 있다" |
| 우리 데이터에 가까운 정보가 있을 때 | 덧붙임 (예: 맛집 → 편의점·마트 수) |

정해 둔 확인 방법 (`backend/guides.py`, LLM 이 지어내지 않도록 코드에 고정)

| 주제 | 안내 | 링크 |
|---|---|---|
| 치안·밤길 | 범죄 주의 구간·CCTV·보안등, 밤에 직접 걸어 보기 | 생활안전지도 |
| 관리비 | 계약 전 중개사무소에 금액·포함 항목 확인 (아파트는 K-apt) | 공동주택관리정보시스템 |
| 보증금 안전·집주인 | 등기부등본(소유자·근저당), 전세보증금 반환보증 | 인터넷등기소, HUG |
| 소음 | 평일 밤·주말 방문 | – |
| 채광·집 상태 | 낮 방문, 곰팡이·결로·수압·배수 | – |
| 이웃·동네 분위기 | 평일 저녁·주말 걸어 보기 | – |
| 반려동물 | 허용 여부 확인, 계약서 특약 | – |
| 주차 | 건축물대장 열람 | 세움터 |
| 침수 | 침수 흔적 지역 | 생활안전지도 |
| 학교 | 주변 학교 정보 | 학교알리미 |
| 실제 매물·현재 시세 | 부동산 앱·중개사무소 ("나와 있는 방", "방 보여줘" 등) | 직방, 다방 |
| 인터넷 | 통신사 확인, 현장 속도 측정 | – |

## 8. Gemini 가 받는 정보 (facts)

| 응답 | 받는 정보 |
|---|---|
| 조건 해석 | 현재 상태(단계·필수 조건·기준), 목적지, 후보 동 이름 목록, 1~5위, 최근 대화 4개, 직전 되묻기 |
| 결과 설명 | 상위 3곳 상세(값·강점·주의), 이번 변경, 순위 변동과 요인별 원인, 상충, 조금 풀면 들어오는 동, 말한 동네·비교, 확인 방법, 첫 결과 여부 |
| 질문 답변 | 현재 조건, 순위 요약(10위까지), 제외 요약(이유), 질문한 동네 상세(순위 또는 제외 이유·완화 조건, 요인별 점수, 비용 구성, 통근 노선, 역, 편의·주점), 코드가 계산한 비교, 확인 방법, 데이터 출처·기간, 최근 대화 6개 |

## 10. 알려진 한계

- 응답 하나에 Gemini 호출 1~2회: 조건 해석 3~5초 + 답변 3~10초
- 확인 방법은 키워드·주제어로 고른다. 표현이 많이 다르면 기본 안내(카카오맵 검색)로 넘어간다
- 산점도 강조는 조건을 통과한 동만 가능 (제외된 동은 지도에서 선택)
- 대화 기록은 최근 4~6개만 넘긴다. 아주 앞의 대화를 가리키면 놓칠 수 있다
- 세션은 서버 메모리에 있어 서버를 다시 켜면 대화가 사라진다
