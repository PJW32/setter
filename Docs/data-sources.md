## 3. API 키가 필요한 데이터

| 키 | 필요도 | 용도 | 비고 |
|---|---|---|---|
| `ODSAY_API_KEY` | 선택 | 통근 교차 확인 | **무료 일일 한도 약 30건** (2026-11-20, 30건쯤에서 `429 Daily quota exceeded`) |
| `GEMINI_API_KEY` | **필수** | 조건 추출, 결과 설명 | 정식(stable) 모델 `gemini-3.8-flash` 고정. 심사 기간(~12/7) 동안 유지, 유료 등급 + 지출 한도 권장 |
| `KAKAO_REST_API_KEY` | **필수** | 동 목록, 대표 지점, 역·편의·술집, **통근(대중교통 경로)** | 장소 검색 일 10만 건, 대중교통 경로 일 1,000건 무료 |
| `DATA_GO_KR_SERVICE_KEY` | 선택 | 실거래가 API (수동 CSV 대신 자동 갱신할 때) | MVP는 수동 CSV로 충분 |

- ODsay에는 **출발·도착 시각 파라미터가 없다** → 기획서의 `arrive_by`는 빼고 "평일 기준 소요 시간"으로 표시
- ODsay `payment`가 성인 카드요금(원)인지 첫 호출로 확인

### ODsay 응답 형태 (확인됨)

정자역 → 판교역 1회 호출 결과:

- `result`: `searchType`, `pointDistance`(직선거리 m), `startRadius`/`endRadius`(700m 안의 정류장·역을 찾음), `busCount`, `subwayCount`, `subwayBusCount`, `path[]`
- `path[]`: 19개 경로. `pathType` 1 지하철 / 2 버스 / 3 버스+지하철
- `path[].info`: `totalTime`(분, 도보 포함), `payment`(원), `busTransitCount`, `subwayTransitCount`, `totalWalk`(m), `totalWalkTime`(-1 = 없음), `totalIntervalTime`, `checkIntervalTime`, `firstStartStation`, `lastEndStation`, `totalDistance`, `trafficDistance`, `mapObj`
- `path[].subPath[]`: `trafficType`(1 지하철 / 2 버스 / 3 도보), `sectionTime`, `distance`, `startName`, `endName`, `lane[].name`(예: 수도권 신분당선), `startExitNo`, `endExitNo`, 좌표 등
- 가장 빠른 경로: 지하철, 8분(도보 4 + 승차 3 + 도보 1), `payment` 2550원 → 신분당선 별도 운임이 포함된 성인 카드요금으로 보임

### 카카오 응답 형태 (확인됨)

- 카테고리 검색 `documents[]`: `id`, `place_name`, `category_group_code`, `category_group_name`, `category_name`(예: `가정,생활 > 편의점 > GS25`), `address_name`, `road_address_name`, `x`, `y`, `distance`(m, 문자열), `phone`, `place_url`
- **`meta.total_count`는 45를 넘어도 전체 개수를 준다** (편의점 800m 49개, 음식점 2km 1,491개). 받을 수 있는 문서는 45개까지(`pageable_count`)지만 **개수 세기는 호출 1번**으로 충분
- 지하철역(SW8)은 **노선별로 따로** 나온다 (`정자역 신분당선`, `정자역 수인분당선`) → 역 이름으로 묶고 노선 목록을 만든다
- `coord2regioncode`: 법정동(`region_type: B`, 예: 정자동 `4113510300`)과 행정동(`H`, `4113554500`)을 함께 준다
- 주소 검색 `"경기도 성남시 분당구 정자동"` → `address.b_code` = `4113510300`, `x`/`y` = 법정동 대표 좌표. 행정동(정자1동 등)도 같이 나오므로 `b_code`가 있는 결과만 쓴다
- 음식점 `category_name`에 `술집` 하위 분류가 있다 → 주점 개수를 카카오로 교차 확인할 수 있음 (상가정보가 기본)

### 통근 값 만드는 규칙 (제안)

- 경로 중 `totalTime`이 가장 짧은 것을 대표로 쓰고, 그 경로의 `payment`를 편도 요금으로 쓴다
- 환승 횟수 = `busTransitCount + subwayTransitCount - 1` (0 미만이면 0)
- 배차 대기 시간(`totalIntervalTime`)은 의미를 더 확인한 뒤 반영 여부를 정한다
- 동 대표 지점에서 700m 안에 정류장·역이 없으면 경로가 안 나올 수 있다 → 이때는 "통근 데이터 없음"으로 표시

## 6. 수집 결과: `data/dongs.json` (2026-11-20)

`python scripts/build_dongs.py` 로 만든다. 응답은 `data/cache/`에 저장돼 다시 돌리면 API를 부르지 않는다 (처음 약 15분, 이후 5초).

### 만드는 과정
1. **법정동 목록**: 시군구 대표 지점에서 400m 격자를 넓혀 가며 카카오 좌표→법정동 변환. 같은 시군구 코드인 점만 따라간다
   → 8개 시군구, **106개 법정동** (분당 18, 수정 17, 중원 9, 수지 7, 기흥 18, 강남 14, 서초 10, 송파 13. 실제 법정동 수와 일치)
2. **대표 지점**: 동 안 격자점마다 반경 300m 편의점 수를 세고, 그 수로 가중한 무게중심에 가장 가까운 격자점
   → 넓은 동에서 산·공원 한가운데가 잡히는 것을 피한다. 104개 동이 이 방식, 편의점이 없는 2개 동은 카카오 법정동 대표 좌표
3. **요인**: 대표 지점 기준으로 아래 값을 모은다

### 한계 (화면·소개서에 표시할 것)
- 카카오 대중교통 시간은 **출발 시각을 지정할 수 없는** 추정값. ODsay보다 길게 나온다 (정자역→판교역: 카카오 16분, ODsay 8분). 대기 시간을 포함하는 것으로 보임

### 7.1 전월세 실거래가 (확인됨)

### 7.2 실제 분포: 성남시 분당구, 2026년 10월 한 달

| | 전체 거래 | 33㎡ 이하 | 그중 월세 > 0 | 보증금 중앙값 | 월세 중앙값 |
|---|---|---|---|---|---|
| 연립다세대 | 85 | 1 | 1 | - | - |
| 단독다가구 | 293 | 137 | 127 | 1,000만원 | 50만원 |
| 오피스텔 | 461 | 183 | 147 | 1,000만원 | 83만원 |

- **원룸 월세는 단독다가구와 오피스텔에서 나온다.** 연립다세대는 33㎡ 이하가 거의 없다
- **두 유형의 월세 차이가 크다** (50만 vs 83만). 동마다 유형 구성이 달라서 섞어서 중앙값을 내면 "오피스텔이 많은 동이 비싸 보이는" 효과가 생긴다
  → 엔진은 유형별로 따로 계산하고, 사용자 선택(오피스텔/다가구/상관없음)을 받는다 (제안)
- **면적 기준이 다르다**: 단독다가구는 계약면적, 오피스텔은 전용면적. 같은 33㎡여도 실제 크기가 다르다 → 유형별 상한을 따로 둘지 결정 필요
- `contractType` 빈값이 일부 있다 (단독다가구 8건, 오피스텔 3건) → "신규만" 필터에서 빈값은 포함
- 동별 쏠림이 크다: 분당 원룸 월세는 정자동·야탑동·분당동·수내동·구미동에 몰림. 운중동·석운동 같은 동은 12개월을 모아도 표본 부족일 가능성이 높다
