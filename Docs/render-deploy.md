# Render 무료 심사용 배포

팀원·심사위원에게 공유하는 단일 프로세스 MVP를 배포한다. `DEPLOY_ACCESS_MODE=public`은 로그인 검사만 생략하고 브라우저별 대화 분리·호출 제한을 유지한다. `basic`은 HTTP Basic 인증도 요구한다. 미설정 시 기존 basic 방식이다. 개인별 회원 계정이나 완전한 보안 보장을 제공하는 구성은 아니다. AI 프롬프트·추천 계산·프론트 소스는 변경하지 않는다.

## 기존 서비스 공개 전환

코드 병합과 fork 갱신 후 기존 `setter-teojeon-lab`의 **Environment**에 `DEPLOY_ACCESS_MODE=public`을 직접 추가하고 재배포한다. Blueprint Auto Sync는 꺼져 있으므로 YAML만 바꿔서는 기존 환경에 반영되지 않는다. **Blueprint Manual Sync는 누르지 않는다.** 기존 `DEPLOY_USERNAME`·`DEPLOY_PASSWORD`가 남아 있어도 공개 모드에서는 무시한다. `DEPLOY_SESSION_SECRET`·API 키·origin은 유지한다. 새 시크릿 브라우저에서 로그인 창 없이 접속되는지 확인한다.

공개 모드도 아래 대화·요청·동시 실행·본문 크기·호스트·origin 보호를 유지한다. 아래 Basic 인증과 인증 실패 제한 설명은 basic 모드에만 적용한다. public에서도 서명 비밀값과 정확한 origin 없이는 실행되지 않는다. 누구나 호출 가능하므로 공통 한도 소진과 외부 API 비용 가능성이 있으며 메모리 기반 제한은 재시작 때 초기화되어 과금 상한을 보장하지 않는다. 기존 쿠키 서명 비밀값은 유지하므로 브라우저별 대화 접근은 기존 방식대로 동작한다. 복귀는 아이디·암호를 유지한 상태에서 `DEPLOY_ACCESS_MODE=basic`으로 바꾸고 재배포한다.

## 1. 비용과 데이터 유지

2026-11-22 공식 문서 기준으로 Render Free 웹 서비스와 기본 `onrender.com` HTTPS를 사용한다. `render.yaml`에는 무료 웹 서비스 하나만 있으며 유료 디스크나 DB는 없다. 결제수단을 등록하지 않고 Free를 유지한다. 대역폭 한도에 도달하면 서비스가 중지되고 빌드 한도에 도달하면 새 빌드가 중지될 수 있다. Gemini(Vertex 포함)·카카오·공공데이터 API 계정의 비용·쿼터는 별개다. 특히 현재 Gemini 연동은 Vertex를 사용하므로 무료라고 단정하지 말고 팀원의 실제 프로젝트 과금 상태를 확인한다.

15분 미사용 시 절전되며 다음 접속은 약 1분 걸릴 수 있다. 재시작·재배포·절전 시 실행 중 파일 변경과 메모리 대화가 사라진다. 빌드에서 만든 실거래 스냅샷은 배포 산출물에 포함되지만, 실행 중 추가한 지역·시설·통근 자료는 영구 보관되지 않는다. 별도 영구 DB가 없는 이번 구성에서는 새 서버의 첫 검색이 오래 걸릴 수 있다.

공식 근거: [무료 범위](https://render.com/docs/free), [HTTPS](https://render.com/docs/tls), [환경변수](https://render.com/docs/configure-environment-variables), [Python 런타임의 Node/npm 지원](https://render.com/docs/native-runtimes).

## 2. Git에 올리는 것

새 브랜치의 코드·테스트·`.env.example`·`render.yaml`만 커밋하고 리뷰 후 `master`에 병합한다. `.env`, 실제 암호·키, `data/store.sqlite`, `data/rent_snapshot.sqlite`, 캐시, 이전에 생성한 배포용 ZIP은 공개 GitHub에 올리지 않는다.

이번 배포 빌드는 로컬 DB 업로드 대신 `scripts/prewarm_rent.py`로 서버에서 국토부 실거래를 준비한다. 13개 지역 코드 × 현재 설정의 3유형 × 12개월 = 468묶음이며 추가 페이지 요청이 생길 수 있다. 국토부 API 사용량과 빌드 시간이 발생한다. 네트워크·쿼터·키 문제로 일부라도 실패하면 빌드가 실패하여 불완전한 새 버전을 배포하지 않는다. 신고 정정 등으로 로컬의 138,831건과 서버의 새 수집 건수는 다를 수 있다.

카카오 기반 지역·시설·통근 자료는 빌드에서 수집하거나 묶음으로 배포하지 않는다. 기존 서비스의 해당 API 조회·저장 동작은 이번 변경으로 바뀌지 않는다. 공개 서비스 확대 전 공급자의 저장·재사용 조건을 확인해야 한다. 상세: [사전 수집 운영](data-prewarm.md).

## 3. Render에서 사용자가 할 일

1. GitHub 계정으로 Render에 가입하고 계정의 2단계 인증을 설정한다. 결제수단은 등록하지 않는다.
2. 이 PR이 `master`에 병합된 뒤 **New → Blueprint**에서 `PJW32/setter`를 연결한다. 연결할 저장소 권한은 이 저장소로 한정한다.
3. Blueprint 묶음 이름은 팀 이름 터전연구소를 반영한 `teojeon-lab`으로 지정한다. 구성에 `setter-teojeon-lab` 웹 서비스 **1개**, **Free**, Singapore가 표시되는지 확인한다. 유료 항목이 나타나면 진행하지 않고 설정을 확인한다.
4. 아래 비밀값을 Render 입력란에 직접 입력한다. 채팅·PR·스크린샷에는 값을 공유하지 않는다. 사용자 입력을 마치고 Blueprint를 생성하면 실제 빌드와 배포가 시작된다.

| 환경변수 | 입력 |
|---|---|
| `DEPLOY_USERNAME` | 심사용 접속 아이디. 콜론 없이 64자 이내 |
| `DEPLOY_PASSWORD` | 비밀번호 관리자로 만든 20자 이상의 무작위 접속 암호 |
| `DEPLOY_SESSION_SECRET` | Blueprint가 무작위 값을 자동 생성. 접속 암호와 다른 비밀값 |
| `GEMINI_API_KEY` | 현재 코드의 Vertex 연동에 맞는 팀 API 키 |
| `KAKAO_REST_API_KEY` | 카카오 REST API 키 |
| `DATA_GO_KR_SERVICE_KEY` | 공공데이터포털 서비스 키 |

`APP_ENV=production`, `DEPLOY_RENT_CODES`, Python/Node 버전은 Blueprint에 지정되어 있다. `APP_ORIGIN`은 기본 Render 주소를 쓸 때 입력하지 않는다. `RENDER_EXTERNAL_URL`을 자동 사용한다. 사용자 도메인을 연결하면 `APP_ORIGIN`에 해당 HTTPS 주소를 정확히 지정한다. 이 배포는 프론트와 API를 같은 주소에서 제공한다. Vercel 등 다른 도메인의 프론트를 연결하려면 인증·쿠키·CORS 설계를 별도로 수정해야 한다.

자동 배포는 꺼져 있다. 이후 `master` 갱신을 배포하려면 Render에서 수동 배포한다. 암호 변경 시 서비스 환경변수에서 수정하고 재배포한다. 쿠키 서명 비밀값 변경 시 기존 브라우저의 대화 접근이 끊긴다. 팀원 퇴장이나 유출 의심 시 공유 암호와 관련 키를 교체한다.

## 4. 적용되는 접근 제한

동시 추천 처리 상한은 5개다. 6번째 요청은 대기열에 넣지 않고 503과 Retry-After로 재시도를 안내한다. 같은 대화의 중복 요청은 기존 409를 유지한다. API 120회/분·추천 12회/분·100회/24시간 제한은 변경하지 않는다. 무료 서버 자원은 늘지 않으므로 5개 동시 수집/AI 호출의 속도와 메모리 안정성을 보장하지 않는다. 내부 시군구 수집 2곳·공급자 HTTP 연결 최대 8개는 유지하며, 실제 서버 부하 검증은 별도로 필요하다.

- `/healthz`만 인증 없이 `{"ok": true}`를 반환한다. 상태 점검용이며 키·지역·통계는 제공하지 않는다.
- 화면·정적 파일·모든 `/api/*`는 서버에서 아이디·암호를 검증한다. API만 직접 호출해도 인증을 통과해야 한다. Render나 `APP_ENV=production`에서 인증 값이 없거나 약하면 앱 시작을 중단한다.
- 브라우저마다 서명된 무작위 소유자 쿠키를 발급한다. HTTPS에서 `Secure`, `HttpOnly`, `SameSite=Strict`, `__Host-` 접두사를 사용한다. 다른 브라우저가 대화 ID를 알아도 해당 대화의 조회·메시지·가정 비교는 404다. 브라우저 간 대화 공유 기능은 없다.
- 대화 ID는 128비트 난수다. 1시간 미사용 대화는 다음 세션 요청 때 삭제한다. 브라우저당 3개, 서버 전체 16개를 제한한다. 대화의 저장 메시지가 200개 이상이면 새 대화를 요구한다. 재시작 시 모든 대화는 사라진다.
- 분당 API 120회, 추천·가정 비교 분당 12회 및 최근 24시간 100회, 응답 처리 동시 5개로 제한한다. 모두 서버 프로세스 전체 기준이다. 상태 확인·화면·정적 파일은 API 카운트에서 제외한다. 24시간 한도는 외부 공급자 과금의 하드 캡이 아니며, 재시작 시 카운트가 초기화된다.
- 인증 실패는 직접 연결 상대별 분당 12회로 제한한다. 시작 명령은 전달 IP 헤더를 신뢰하지 않으므로 Render 프록시 뒤에서는 여러 사용자가 이 제한을 함께 적용받을 수 있다. 정확한 사용자별 방화벽 제한이나 DDoS 방어를 대신하지 않는다.
- 변경 요청 본문은 선언된 크기뿐 아니라 실제 수신 크기도 최대 16KiB다. 다른 Origin이나 cross-site 브라우저에서 보내는 변경 요청을 거부한다. CORS만으로 접근 인증을 대신하지 않는다.
- 배포 모드에서 `/docs`, `/redoc`, `/openapi.json`, DB·숨김 파일·소스맵 경로는 공개하지 않는다. 응답 캐시를 막고 프레임 삽입·콘텐츠 추측을 제한하는 헤더를 추가한다.
- SSE의 공급자 진단 `info`와 오류 상세는 전달하지 않는다. Uvicorn 요청 접근 로그를 끄지만 Render 플랫폼 자체 로그 정책이나 사용자에게 이미 전달한 정상 추천 정보를 통제하는 기능은 아니다.

HTTP Basic 인증은 브라우저가 자격증명을 기억할 수 있다. 공유 컴퓨터에서는 시크릿 창을 사용하고 사용 후 창을 닫는다. 암호를 아는 사람의 정상 사용·결과 복사까지 차단하지 않는다. 일반 회원 서비스로 확대할 때는 개인별 계정·권한·로그아웃·운영 감사를 별도 설계한다.

## 5. 배포 확인

기존 `saeteo-preview`를 이름 변경할 때는 YAML만 동기화하지 않는다. Render의 기존 서비스 Settings에서 이름을 `setter-teojeon-lab`으로 변경하고, 동일한 서비스 ID가 유지되는지 확인한 뒤 Blueprint 변경을 반영한다. Blueprint 묶음의 표시 이름은 별도 Settings에서 `teojeon-lab`으로 변경한다. 동기화 목록에 기존 서비스 업데이트 대신 새 서비스 생성이 나타나면 진행하지 않는다. 기존 서비스를 삭제하거나 두 번째 서비스를 생성할 필요는 없다. 실제 서비스 URL 변경 여부도 확인하고, `APP_ORIGIN`을 직접 설정했다면 실제 HTTPS 주소로 맞춘다. 기본 설정은 `RENDER_EXTERNAL_URL`을 사용한다.

지도 타일 요청에는 `strict-origin-when-cross-origin` 정책을 적용한다. 외부 지도 서버에 사이트 origin만 보내고 상세 경로·쿼리는 보내지 않는다. `no-referrer`는 OSM의 웹 요청 출처 확인 정책과 충돌하므로 사용하지 않는다.

1. 새 시크릿 창에서 서비스 주소에 접속해 아이디·암호 창이 나오는지 확인한다.
2. 잘못된 암호와 인증 없는 `/api/meta` 요청이 401인지 확인한다.
3. 올바른 암호로 화면·지도·대화가 동작하는지 확인한다. 실제 추천은 외부 API 호출과 비용이 발생할 수 있다.
4. 다른 시크릿 브라우저 프로필에서 첫 브라우저의 대화 주소를 조회하면 404인지 확인한다.
5. `.env`, `/data/store.sqlite`, `/data/rent_snapshot.sqlite`, `/docs`가 다운로드·열람되지 않는지 확인한다.
6. `/healthz`에는 `ok`만 있고 로그에 키·암호가 노출되지 않는지 확인한다. 실제 비밀값을 포함한 명령이나 로그를 공유하지 않는다.

자동 테스트: `python -m unittest discover -s tests -v`. 인증 우회·변조 쿠키·브라우저 간 대화 접근·분할 본문·다중 클라이언트 제한·동시 스트림·오류 상세 차단을 가짜 데이터로 검증한다. 실제 Render 배포, Linux 빌드, 공급자 인증·과금 및 실제 웹 브라우저 동작 확인은 별도다. 모든 설정은 위험을 낮추는 조치이며 침해가 절대 발생하지 않는다는 보장은 아니다.
