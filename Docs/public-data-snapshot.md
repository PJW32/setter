# 공공 시설 데이터 사전 구축

기존 실거래 스냅샷과 별도로 소상공인시장진흥공단 상가 원본의 업종·좌표를 SQLite로 준비한다. 현 단계는 검증용이며 추천 서비스는 이 DB를 아직 읽지 않는다. 시설 출처 변경으로 인한 대표 지점·시설 수·추천 순위의 차이를 검증하기 전에는 자동 전환하지 않는다.

## 원본과 권한

- 공식 원본: https://www.data.go.kr/data/15083033/fileData.do
- 2026-09-30 기준, 분기 갱신, 무료, 이용허락범위 제한 없음(2026-11-23 확인).
- 포털의 다운로드 제한과 인증 요청을 따른다. 로그인·CAPTCHA가 필요하면 직접 다운로드하고 인증을 우회하지 않는다.
- 도시철도 역 후보 자료: https://www.data.go.kr/data/15013205/standard.do (무료, 이용허락범위 제한 없음). 이 수집기에는 아직 포함하지 않는다.
- 카카오 응답, 인증키, 연락처, 상호명, 상세 주소는 새 DB에 넣지 않는다.

## 실행

포털에서 공식 상가 ZIP을 다운로드한 다음 프로젝트 루트에서 실행한다. Python 표준 라이브러리만 사용하며 네트워크·Gemini 호출은 없다.

```bash
python -X utf8 scripts/build_public_places.py data/raw/sbiz-20260930.zip --as-of 2026-09-30
```

기본 대상은 실거래 스냅샷과 동일한 13개 시군구다. 전체 CSV를 스트리밍하며 해당 지역의 편의점(G20405)·약국(G21501)·주점(중분류 I211)만 남긴다. 업소 식별자·법정동 코드·업종 코드/명·좌표를 저장하고 다른 업종은 제외 건수만 기록한다. 원본 ZIP을 디스크에 압축 해제하지 않는다. 카카오 분류와 일치한다고 가정하지 않으며 슈퍼마켓을 대형마트로 간주하지 않는다.

출력은 `data/public_places-essential.sqlite`다. `metadata` 테이블의 `manifest`에 출처·이용허락범위·원본 기준일·구축 시각(UTC)·입력 SHA-256·지역/업종별 건수·업종 필터·제외 건수·좌표 오류/법정동 코드 누락 건수를 기록한다. 구축 시각을 원본 수집 시각으로 표시하지 않는다. 이전 전체 업종 DB는 비교용으로 유지한다.

필수 열 누락, 요청 지역 자료 없음, 업소 식별자 충돌, 무결성 검사 실패 시 새 DB를 발행하지 않는다. 좌표 오류는 제외하고 보고한다. 기존 DB를 덮어쓰지 않으므로 갱신 시 `--output data/public_places-next.sqlite`로 새 파일을 만들어 비교한다. ZIP·DB는 Git에 올리지 않는다.

## 서비스 연결 전 확인

1. 요청 13개 지역의 수록 여부, 좌표 누락, 업종 분류/원본 기준일을 확인한다.
2. 같은 위치와 반경에서 기존 시설 수와 비교한다. 중복 업소와 대형마트 정의 차이를 검토한다.
3. 법정동 경계·대표 지점은 별도 공공 원본과 기존 400m 격자 규칙으로 검증한다. 상가 DB만으로 법정동 탐색을 대체하지 않는다.
4. 역 좌표·노선·환승 중복과 통근 API 처리는 별도 구현한다.
5. 빈 환경 복원·검색 비교·메모리 사용량을 확인한 뒤 Render 빌드에 연결한다.

따라서 이 DB 구축만으로 5분 첫 검색이 해결됐다고 판정하지 않는다. Render 설정·추천 엔진·AI·프론트는 이번 변경 대상에 포함하지 않는다.

## 2026-11-23 로컬 구축 결과

- `data/public_places-essential.sqlite`: 12,813건, 2,117,632바이트(약 2.1MB). 기존 약 47MB에서 약 95.5% 감소했다.

- 이전 전체 업종 DB에서 같은 필터로 조회한 행과 축소 DB가 일치함을 확인했다. 업소 좌표·업종 값은 변경하지 않았다. 남긴 행의 좌표 오류·법정동 코드 누락은 각각 0건이다.
- `data/raw/public-places-essential-20260930-v2.zip`: 702,882바이트. DB·출처/체크섬 매니페스트 포함. 빈 임시 폴더 복원 후 체크섬·건수·무결성 검사를 통과했다.
- 기존 원본·전체 업종 DB·v1 묶음은 비교용으로 유지한다. 이 축소는 데이터 용량을 줄이며, 서버 추천에는 아직 연결하지 않았으므로 첫 검색 속도 개선 실측은 아니다.

### 비교용 초기 전체 업종 구축

- 공식 상가 원본 ZIP: 349,070,686바이트. SHA-256 `c83b30e7a1d1144864a91d0e1818abf360f565972878d6e3c88d75ceafe2286a`.
- 대상 13개 시군구 모두 수록, 총 269,167건. DB 47,173,632바이트. 좌표 오류 0건, 법정동 코드 누락 0건. 이는 완전성이나 현재 영업 여부를 보증하는 수치는 아니다.
- 편의점 G20405 4,849건, 약국 G21501 2,521건, 주점 I211 5,443건. 대형마트에 해당하는 업종은 이 원본에서 확인되지 않아 카카오 MT1을 대체하지 않는다.
- 검증용 묶음 `data/raw/public-places-20260930-v1.zip`: 14,833,117바이트. DB와 SHA-256/출처 매니페스트를 포함한다. 별도 임시 폴더에서 체크섬·269,167건·SQLite 무결성 검사를 통과했다. 서비스 전체의 빈 환경 추천 테스트는 아니다.

- 실제 Render 배포, 기존 시설/대표 지점과의 동등성 비교, 법정동 경계 구축은 아직 수행하지 않았다. ZIP과 DB는 Git 제외 대상이므로 코드 PR을 머지해도 서버로 전송되지 않는다.

## 읽기 전용 조회와 기존 시설 수 비교

`collectors/public_places.py`는 SQLite를 읽기 전용으로 열고 좌표 인덱스의 경계 상자와 기존 `region.meters`와 같은 근사 거리식을 이용해 반경 내 업소를 센다. 조회 지점의 시군구가 없으면 오류를 내고, 다른 수록 시군구에 있는 가까운 업소도 집계한다. 해당 지역의 데이터가 있다는 사실만으로 반경 전체가 수록됐다고 보증하지 않는다. 지역 외곽의 누락 문제 때문에 운영 수집기에서는 아직 호출하지 않는다.

```bash
python -X utf8 scripts/compare_public_places.py
```

이 명령은 저장된 동 대표 지점의 기존 시설 수와 새 DB 값을 비교하고 업종별 일치 건수·차이 통계를 출력한다. 외부 API·Gemini 호출, 기존 DB 수정, 개별 카카오 결과의 새 배포 묶음 생성은 하지 않는다.

2026-11-23 로컬 기존 302개 동 비교에서 조회 906회가 약 0.74초였다. 편의점은 141/302곳, 약국은 198/302곳, 주점은 295/302곳에서 일치했다. 절대 차이의 최댓값은 각각 10·9·11개였다. 과거 저장 값과의 비교이므로 차이를 모두 새 자료의 오류로 판단하지 않는다. 첫 검색 전체 속도나 대표 지점·순위 유지가 검증된 결과도 아니다.

다음 연결 조건은 반경 주변 지역까지 수록 범위를 확보하고, 자료 기준일·업종 정의·거리식 차이를 검토한 뒤 대표 지점과 순위 변화를 비교하는 것이다. 현재 자동 전환이나 선택 설정은 제공하지 않으며, 기본 추천 동작을 유지한다.

## 경계 누락과 순위 비교 결과

같은 공식 원본으로 전국 필요 업종 173,898건의 검증 DB(29,360,128바이트)를 별도 생성했다. 배포 후보인 2.1MB 파일을 덮어쓰거나 운영에 연결하지 않았다.

```bash
python -X utf8 scripts/build_public_places.py data/raw/sbiz-20260930.zip --as-of 2026-09-30 --all-regions --output data/public_places-national-validation.sqlite
python -X utf8 scripts/audit_public_places.py
```

`--all-regions`도 편의점·약국·주점만 보존한다. 감사 명령은 원본 SHA-256과 기준일이 같은지 확인한 뒤 로컬 저장소를 읽기 전용으로 열어 `data/raw/public-places-audit.json`에 비교 결과를 저장한다. 외부 API나 AI를 호출하지 않는다.

302개 동의 500m 집계 중 7개 동·15개 업종 집계에서 지역 경계 밖 업소가 빠진 것을 확인했다. 풍납동·영화동·내손동·포일동·초평동·고매동·농서동이 해당한다. 영화동 주점은 13개 지역 DB 138개 → 전국 DB 149개로 기존 저장값 149개와 일치했다. 다만 전국 DB를 사용해도 기존 값과 다른 집계는 906개 중 265개였으므로 경계 누락만이 차이의 원인은 아니다. 기준일·업종 정의·거리식·기존 수집 상태 등의 영향은 추가 검증해야 한다.

기존 판교역 통근 데이터가 있는 71개 후보를 사용하고, 대표 지점·역·통근·대형마트·거래·점수 엔진을 고정한 채 편의점·약국·주점만 교체했다. 조건은 보증금 1,000만 원·통근 50분 이하이며 우선순위 미지정은 기존 기본 가중치다.

| 조건 | 기존 상위 3곳 | 전국 공공 시설 수 적용 시 상위 3곳 |
|---|---|---|
| 월세 60만 원 이하 | 이매동·풍덕천동·서현동 | 동일 |
| 월세 50만 원 이하 | 이매동·서현동·수내동 | 이매동·서현동·풍덕천동 |
| 월세 60, 역 접근성 매우 중요 | 이매동·풍덕천동·서현동 | 동일 |
| 월세 60, 조용함 매우 중요 | 이매동·수내동·서현동 | 이매동·서현동·수내동 |
| 월세 60, 생활 편의 매우 중요 | 풍덕천동·이매동·서현동 | 동일 |

전체 통과 후보 수는 각 시나리오에서 유지됐으나 전체 순위는 달라졌다. 대표 지점을 편의점 분포로 재산정하면 추가 변화가 생길 수 있으며 이번 검증에서는 수행하지 않았다. 따라서 기존 성능·결과를 보존하는 최적화로 판정하지 않고 전환을 보류한다.
